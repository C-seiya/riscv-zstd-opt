## 第一章 项目概述与目标

### 1.1 背景与动机

RISC-V 作为开放指令集架构正在快速进入服务器、边缘计算等基础软件领域，但与 x86/ARM 相比，其**基础软件库的生态成熟度与性能调优积累仍然不足**。压缩库是数据库、文件系统、网络传输等基础设施的核心依赖——RocksDB、SQLite（ZIPV）、Linux 内核（BTRFS/F2FS/Zswap）、K8s 容器镜像分发（containerd 预解压）均深度依赖 Zstd。

在缺乏原生 RISC-V 硬件的条件下，如何定位热点、量化优化收益，是 RISC-V 软件生态建设的关键问题。本项目给出了一个**从指令级剖析出发、以真实基准验证、面向上游可合并**的完整优化工作流。

### 1.2 项目目标

1. **组件一（工具）**：自研 RISC-V 指令混合度分析工具，从 QEMU `-d in_asm` 指令轨迹中统计指令类型分布（算术/访存/分支/跳转/其他），为热点定位与优化收益量化提供数据基础；
2. **组件二（库优化）**：对 Zstd 1.5.6 压缩库进行热点函数定位（`ZSTD_updateDUBT`）与**批量预计算哈希值**优化，在不改变压缩输出正确性的前提下降低动态指令数；
3. **框架适配**：将优化后的 Zstd 接入 **RocksDB**（BlockBasedTable 压缩路径）与 **SQLite**（Blob 压缩存储扩展），证明优化的真实上层价值；
4. **验证方式**：全流程在 QEMU 模拟环境中完成交叉编译、运行与功能验证；
5. **演进路线**：为后续 RVV 1.0 向量化改造预留接口与分析基线（"向量化预备"）。

### 2.2 组件一：RISC-V 指令混合度分析工具

**定位**：通用 RISC-V 指令轨迹分析器，不绑定 Zstd，可分析任意 qemu-riscv64 `-d in_asm` 输出。

**功能设计**：
- 解析 QEMU `-d in_asm` 翻译块日志，提取全部已执行指令的汇编助记符；
- 按五大类归类统计：**算术（arith）、访存（load/store）、分支（branch）、跳转（jump）、其他**；
- 单日志模式：输出指令总数与各类占比；
- **双日志 diff 模式**：输入优化前/后两份日志，自动输出逐类差值与百分比变化的 Markdown 报告——这是本项目的核心创新点之一，使"优化了多少条指令"从手工统计变成可复现的自动化流程；
- 输出同时支持终端表格与 Markdown 报告文件，直接嵌入参赛文档。

**技术要点**：
- 采用固定大小哈希桶 + 助记符前缀树匹配（区分 `lw`/`ld`/`sw` 等访存指令与 `add`/`addi`/`mul` 等算术指令）；
- 流式读取，2.9MB 级别日志秒级完成，可扩展至 GB 级轨迹。

### 2.3 组件二：Zstd 批量预计算哈希值优化

**热点定位过程**：
1. 交叉编译 Zstd 1.5.6 → QEMU 运行压缩 benchmark → `-d in_asm` 抓取指令轨迹；
2. 分析工具统计显示：算术指令占比 42.35%，为第一大类；
3. 结合日志人工比对，热点集中在 `ZSTD_updateDUBT`（双桶搜索树的更新函数），其内部循环对每个候选位置逐个调用 `ZSTD_hashPtr` 计算哈希——存在**重复的地址计算与哈希种子加载**，且相邻哈希计算的地址增量固定，适合合并为批量预计算。

**优化方案（批量预计算）**：
- 在进入 `ZSTD_updateDUBT` 主循环前，**一次性预计算循环所需的全部哈希值**并存入栈上缓冲；
- 主循环改为查表取值，消除循环体内的地址重算、立即数装载与部分依赖链；
- 等价性论证：哈希函数为纯函数（输入相同输出相同），预计算不改变任何比较顺序与匹配决策，**压缩输出位级一致**（由正确性测试验证，见第四章）。

**优化效果**（QEMU 指令级，完整数据见《03_性能对比报告》）：

| 指标 | 优化前 | 优化后 | 变化 |
|------|--------|--------|------|
| 总指令数 | 38,218 | 38,128 | **↓ 90 条 (0.24%)** |
| 算术指令 | 16,187 (42.35%) | 16,153 (42.37%) | ↓ 34 条 |
| 访存指令 | 12,238 (32.02%) | 12,197 (31.99%) | ↓ 41 条 |
| 分支指令 | 3,884 (10.16%) | 3,877 (10.17%) | ↓ 7 条 |
| 跳转指令 | 1,754 (4.59%) | 1,748 (4.58%) | ↓ 6 条 |
| 其他指令 | 4,155 (10.87%) | 4,153 (10.89%) | ↓ 2 条 |

> 说明：QEMU 用户态 `-d in_asm` 记录的是翻译块级轨迹，单条基准的指令计数粒度有限；0.24% 的降幅虽然数值不大，但验证了"批量预计算 → 减少算术与访存指令"的因果链方向正确。该优化在真实硬件上随 DUBT 匹配深度增加收益会放大（详见 5.2 向量化预备）。

### 2.4 框架适配一：RocksDB

- **构建方式**：通过国内镜像克隆 RocksDB 源码，在 riscv64 交叉工具链 + RuyiSDK 虚拟环境（`~/rocksdb-env`）下编译静态库 `librocksdb.a` 与 `db_bench` 基准程序；
- **依赖处理**：gflags、snappy、lz4、zstd-dev 均以 riscv64 版本安装，zstd 链接为**本项目优化后版本**；
- **验证路径**：`db_bench --benchmarks=fillseq` 在 qemu-riscv64 下跑通写入路径（压缩发生在 SSTable 落盘时，即 BlockBasedTable 的 zstd 压缩路径），随后同样以 `-d in_asm` 抓取指令轨迹，用组件一对比分析 RocksDB 场景下的指令混合度变化。

### 2.5 框架适配二：SQLite

- **构建方式**：交叉编译 SQLite amalgamation（单文件 `sqlite3.c`）为 riscv64 库；
- **适配设计**：自研 `sqlite_zstd_bench`——以 SQLite 作为 KV 存储框架，将 4KB~1MB 压缩友好型 Blob 先经 Zstd 压缩再写入，读出时解压校验；
- **演示价值**：证明"优化后的 Zstd 可被第二个主流存储框架直接复用"，同时提供**框架级端到端指标**（插入吞吐、存储放大、数据完整性校验），弥补纯指令级指标的单一性。

### 2.6 关键设计决策

| 决策点 | 选择 | 理由 |
|--------|------|------|
| 剖析手段 | QEMU -d in_asm 指令轨迹 | 无需真实硬件；指令级粒度足以支撑优化方向判断与回归对比 |
| 优化切入点 | 批量预计算哈希 | 纯函数性质保证等价性；为 RVV 向量化哈希计算铺路 |
| 第二框架 | SQLite（而非 PyTorch） | PyTorch 在 qemu-riscv64 下不可行（无 riscv64 轮子、编译量过大）；SQLite 轻量、可完整验证，同为存储类框架与 RocksDB 形成互补 |
| 指标体系 | 指令混合度 + 压缩比 + 框架吞吐 | 指令级（微观）与框架级（宏观）双层指标，避免单一指标误导 |

### 4.3 已知限制与诚实披露

1. QEMU 用户态 `-d in_asm` 的指令计数为翻译块级轨迹，不是全部动态指令的精确计数；
2. 0.24% 的指令数降幅属于**方向性验证**级别收益，真实收益需在硬件上评测（这是后续向量化工作的动机）；
3. QEMU 模拟不含真实流水线/缓存行为，吞吐指标（55.5 MB/s）仅用于功能验证，不作为性能结论。

## 第五章 总结与展望

### 5.1 项目成果

1. **完整闭环**：剖析工具 → 热点定位 → 库优化 → 双框架适配 → QEMU 验证 → 文档/演示，全链路可复现；
2. **组件一**（分析工具）具备单日志统计与双日志自动 diff 两种模式，输出可直接嵌入文档；
3. **组件二**（Zstd 优化）在不改变压缩输出的前提下实现指令数下降，验证了优化假设；
4. **两个框架**（RocksDB / SQLite）均以优化后 Zstd 链接，提供框架级验证。

### 5.2 向量化预备（下一步路线）

1. **RVV 1.0 哈希批量化**：批量预计算缓冲天然适合 `vmerge`/`vxor`/`vsll` 的向量哈希计算（8 个 u64 哈希/向量寄存器），预期算术指令再降一个数量级；
2. **`ZSTD_count` 匹配循环向量化**：`__builtin_memcpy` 对比模式可改写为 `vle64` + `vxor` + `vmsne` 的向量比较；
3. **工具升级**：analysis_v2 增加 RVV 指令子类统计（`v*.vv`/`v*.vi`/`vl*`/`vs*`），量化向量化前后向量指令占比；
4. **真实硬件验证**： migrating to VisionFive 2 / SOPHON SG2042 等 RISC-V 硬件，补充 perf 级硬件计数器数据。

### 5.3 结语

本项目的核心价值不在单点 0.24% 的指令数下降，而在于**建立了一套无硬件条件下可复现的 RISC-V 基础库优化方法论**——指令轨迹剖析驱动、等价性保证的代码变换、双框架端到端验证、自动化的对比报告——并以此为 RVV 向量化铺平了道路。

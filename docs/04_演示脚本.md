# 动态演示脚本（3 分钟演示视频）

**项目**：面向 RISC-V 的 Zstd 压缩库性能剖析与优化实践
**演示形式**：屏幕录制（WSL 终端 + 浏览器看板），配旁白
**总时长**：3 分钟（180 秒）

---

## 一、分镜脚本

### 镜头 1｜项目概述（0:00 – 0:25，25 秒）

- **画面**：`demo/perf_dashboard.html` 顶部（标题 + 四个徽章 + KPI 卡片）
- **旁白**：
  > "我们的项目是《面向 RISC-V 的 Zstd 压缩库性能剖析与优化实践》。包含两个组件——自研的 RISC-V 指令混合度分析工具，和 Zstd 压缩库的批量预计算优化；并适配了 RocksDB 与 SQLite 两个上层框架，全流程在 QEMU 模拟环境中验证。"

### 镜头 2｜环境展示（0:25 – 0:50，25 秒）

- **画面**：WSL 终端，依次执行：
  ```bash
  qemu-riscv64 --version            # QEMU 10.2.1
  riscv64-linux-gnu-gcc --version   # 交叉工具链
  ls -lh ~/rocksdb/librocksdb.a ~/rocksdb/db_bench   # RocksDB 产物
  ```
- **旁白**：
  > "开发环境是 WSL2 Ubuntu，使用 QEMU 10.2.1 用户态模拟运行 RISC-V 程序，配合 riscv64 交叉工具链和 RuyiSDK 虚拟环境。RocksDB 静态库和 db_bench 基准程序均已完成交叉编译。"

### 镜头 3｜组件一：分析工具（0:50 – 1:20，30 秒）

- **画面**：终端执行：
  ```bash
  # 单日志模式
  ./analysis_v2 single ~/zstd_inst.log -t
  # 双日志 diff 模式（本项目的核心演示）
  ./analysis_v2 diff ~/zstd_inst.log ~/zstd_inst_opt.log -t
  ```
  展示输出的分类统计表与 diff 表
- **旁白**：
  > "这是自研的指令混合度分析工具。单日志模式统计算术、访存、分支、跳转等六大类指令分布；diff 模式自动对比优化前后的两份 QEMU 指令轨迹，直接输出可用于文档的对比报告，并预留了 RVV 向量指令统计，为向量化做准备。"

### 镜头 4｜组件二：Zstd 优化（1:20 – 1:55，35 秒）

- **画面**：切换到看板"指令混合度对比图"与"降幅去向图"
- **旁白**：
  > "优化前，算术指令占比 42% 居首，热点集中在 ZSTD_updateDUBT 的哈希计算。我们采用批量预计算：进入主循环前一次性算好全部哈希值，循环内改为查表。总指令数从 38,218 降到 38,128；降幅 92% 集中在访存和算术指令——与优化机理完全吻合。同时压缩比保持 3.347 不变，正确性无损。"

### 镜头 5｜框架一：RocksDB（1:55 – 2:20，25 秒）

- **画面**：终端执行：
  ```bash
  qemu-riscv64 -L /usr/riscv64-linux-gnu ./db_bench \
      --benchmarks=fillseq --num=10000 --compression_type=zstd
  ```
  展示 fillseq 输出（micros/op、MB/s）
- **旁白**：
  > "第一个框架 RocksDB：db_bench 的写入路径在 QEMU 中跑通，SSTable 落盘使用我们优化后的 zstd 压缩，验证了库级优化向真实存储框架的传导。"

### 镜头 6｜框架二：SQLite（2:20 – 2:40，20 秒）

- **画面**：终端执行：
  ```bash
  qemu-riscv64 -L /usr/riscv64-linux-gnu ./sqlite_zstd_bench \
      --db bench.db --rows 500 --blob-size 4096
  ```
  展示"数据完整性：PASS"
- **旁白**：
  > "第二个框架 SQLite：写入前 zstd 压缩、读回后解压并做 CRC 校验，全部通过——证明优化后的 zstd 可被第二个主流存储框架直接复用。"

### 镜头 7｜总结与展望（2:40 – 3:00，20 秒）

- **画面**：看板"向量化预备路线"表格
- **旁白**：
  > "总结：我们建立了一套无硬件条件下可复现的 RISC-V 基础库优化方法论——指令轨迹剖析驱动、等价性保证的代码变换、双框架端到端验证。下一步将哈希计算迁移到 RVV 向量指令，预期收益放大一个数量级。谢谢观看。"

## 三、备用方案

- 若 db_bench 在 QEMU 中运行超时：改用 `--num=1000` 并在旁白说明"演示环境为模拟器，指标仅证明功能通路"；
- 若录制中出现终端卡顿：预先录好各命令输出，剪辑拼接。

## 四、演示材料的其他用途

- `perf_dashboard.html` 可直接作为**答辩 PPT 的数据页**（评审权重：方案呈现 20% + 动态演示 20%）；
- `analysis_v2 diff` 的实时输出是"动态演示"环节最有说服力的画面——展示工具自动生成报告的过程。

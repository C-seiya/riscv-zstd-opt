# 性能对比报告

**项目**：面向 RISC-V 的 Zstd 压缩库性能剖析与优化实践
**环境**：QEMU 10.2.1 (qemu-riscv64 用户态) + riscv64-linux-gnu 交叉编译
**数据来源**：QEMU `-d in_asm` 指令轨迹 + 自研指令混合度分析工具
**日期**：2026-10-05

---

## 1. 指标体系说明

本项目采用**微观（指令级）+ 宏观（框架级）双层指标**：

| 层级 | 指标 | 采集方式 | 用途 |
|------|------|----------|------|
| 微观 | 指令总数与五类混合度 | QEMU `-d in_asm` + analysis_v2 | 优化方向判断、回归对比 |
| 微观 | 压缩比 | zstd benchmark | 正确性锚点（不应变化） |
| 宏观 | 压缩吞吐（QEMU 模拟值） | zstd benchmark | 仅功能验证，不作性能结论 |
| 宏观 | 框架基准（fillseq / KV 插入） | db_bench / sqlite_zstd_bench | 端到端价值验证 |

> ⚠️ 重要口径说明：QEMU 用户态 TCG 模拟不含真实流水线、缓存与分支预测行为，吞吐数值仅用于确认功能通路；**性能结论以指令混合度变化为准**。

## 2. 核心数据：Zstd 优化前后指令混合度对比

### 2.1 总表

| 指令类别 | 优化前 | 占比 | 优化后 | 占比 | 变化 |
|----------|--------|------|--------|------|------|
| **总指令数** | **38,218** | 100% | **38,128** | 100% | **↓ 90 条 (0.24%)** |
| 算术指令 | 16,187 | 42.35% | 16,153 | 42.37% | ↓ 34 条 |
| 访存指令 | 12,238 | 32.02% | 12,197 | 31.99% | ↓ 41 条 |
| 分支指令 | 3,884 | 10.16% | 3,877 | 10.17% | ↓ 7 条 |
| 跳转指令 | 1,754 | 4.59% | 1,748 | 4.58% | ↓ 6 条 |
| 其他指令 | 4,155 | 10.87% | 4,153 | 10.89% | ↓ 2 条 |

### 2.2 降幅分摊

```
总降幅 90 条的分摊（按类别）：
访存   ████████████████████████████████████████ 41 条 (45.6%)
算术   ██████████████████████████████████       34 条 (37.8%)
分支   ███████                                   7 条 (7.8%)
跳转   ██████                                    6 条 (6.7%)
其他   ██                                        2 条 (2.2%)
```

**解读**：降幅主要由访存（↓41）与算术（↓34）贡献，合计 83/90 = **92.2%**——与"批量预计算消除循环体内重复地址计算与哈希种子加载"的优化机理**完全吻合**（地址计算=算术、取数存数=访存），证实了优化因果链的方向正确性。

### 2.3 基线画像要点

- 算术指令占比 42.35% 居首 → 与 Zstd 哈希计算、匹配比较的运算密集特征一致 → 这也是选择"哈希批量化"作为切入点、并规划 RVV 向量化（哈希可并行计算）的量化依据；
- 访存指令占比 32.02% 次之 → 真实硬件上将通过预计算缓冲提升栈上数据局部性（栈顶连续写入，L1 命中率高），QEMU 中不可见但值得硬件验证。

## 4. 跨框架指令混合度实测（三场景对比）

### 4.1 验证与测试方法

采用**对照验证法**：使用 QEMU 指令跟踪功能（`-d in_asm`）抓取目标程序执行时的完整指令日志，用自研 RISC-V 指令混合度分析工具解析，统计各类指令的数量与占比。通过对比不同框架下的指令分布，量化评估优化效果与适用场景。

### 4.2 测试环境

| 项目 | 配置 |
|------|------|
| 主机系统 | Ubuntu 26.04 LTS (WSL2) |
| 模拟器 | QEMU 10.2.1（RISC-V 64 位用户态模拟） |
| 交叉编译工具链 | riscv64-unknown-linux-gnu-gcc 15.2.0 (RuyiSDK) |
| 优化库 | Zstd 1.5.6（批量预计算哈希优化版） |
| 适配框架 | RocksDB 11.9.0、SQLite 3.46.0 |

### 4.3 三场景实测结果

| 框架 | 总指令数 | 算术指令 | 访存指令 | 分支指令 | 跳转指令 | 其他指令 |
|------|----------|----------|----------|----------|----------|----------|
| Zstd（单库基准） | 38,218 | 42.35% | 32.02% | 10.16% | 4.59% | 10.87% |
| RocksDB（数据库写入） | 590,871 | 43.83% | 41.33% | 6.23% | 7.01% | 1.60% |
| SQLite（嵌入式数据库插入） | 96,272 | 31.42% | 43.53% | 10.33% | 6.17% | 8.55% |

### 4.4 结果分析

1. **Zstd 单库**：算术指令占比最高（42.35%），验证了哈希计算是 Zstd 的核心瓶颈，也是本项目优化的切入点与 RVV 向量化路线的量化依据；
2. **RocksDB**：db_bench 全路径下访存占比升至 41.33%，说明数据库场景中数据搬运（SSTable 写盘、Block 缓存）成为更大的瓶颈；算术类仍占 43.83%（含压缩计算与内存管理运算），印证压缩路径在数据库整体开销中不可忽略；
3. **SQLite**：访存占比最高（43.53%），符合嵌入式数据库 I/O 密集型特征；算术占比相对最低（31.42%），因 B-tree 页面管理以指针/访存操作为主；
4. **关键验证**：`readelf -d` 确认 SQLite 二进制动态链接了 `libzstd.so.1`，证明框架确实调用了优化后的 Zstd 库（RocksDB 为静态链接优化版 Zstd）。

### 4.5 风险识别与评估

| 风险 | 缓解措施 |
|------|----------|
| QEMU 性能波动 | 多次测试取平均值，关注指令数而非绝对时间 |
| 框架版本差异 | 固定使用 RocksDB 11.9.0 和 SQLite 3.46.0 |
| 交叉编译兼容性 | 使用 RuyiSDK 统一工具链，避免版本混用 |
| 指令计数口径 | 统一采用 -d in_asm 翻译块级轨迹口径，前后一致可比 |

## 5. 结论

1. 优化在指令级实现**净下降 90 条（0.24%）**，且降幅 92.2% 集中在算术+访存，与优化机理吻合；
2. 压缩比 3.347 保持不变，性能优化未以正确性为代价；
3. **三场景实测**证明分析工具的跨框架通用性：Zstd（算术密集）、RocksDB（算术+访存并重）、SQLite（访存密集）画像差异明显，为后续按框架定制的优化方向提供了直接依据；
4. 两个框架均确认链接优化版 Zstd（SQLite 动态链接 `libzstd.so.1` 经 `readelf -d` 验证），库级优化向框架传导的链路成立；
5. 在无真实 RISC-V 硬件条件下，完成了"优化方向正确 + 框架可传导"的验证闭环，为 RVV 向量化（预期 5~10 倍加速）建立了可对比基线。

## 6. 附录：复现命令

```bash
# 基线/优化版指令轨迹
qemu-riscv64 -L /usr/riscv64-linux-gnu -d in_asm ./zstd ... &> ~/zstd_inst.log
# 双日志 diff
./analysis_v2 diff ~/zstd_inst.log ~/zstd_inst_opt.log -o diff_report.md
# RocksDB 框架基准
qemu-riscv64 -L /usr/riscv64-linux-gnu ./db_bench --benchmarks=fillseq --num=10000 --compression_type=zstd
# SQLite 框架基准
qemu-riscv64 -L /usr/riscv64-linux-gnu ./sqlite_zstd_bench --db bench.db --rows 500 --blob-size 4096
# 链接证据
readelf -d ./sqlite_zstd_bench | grep zstd
```
